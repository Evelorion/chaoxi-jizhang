# 04 · 数据模型

> 所有数据都存在**一个加密的账本文件**里（AES-GCM，口令派生密钥），
> 结构是 JSON；下面每个字段都对应序列化/反序列化代码，改字段必须同时改两处。
> 相关文件：`lib/src/app.dart`（模型定义与序列化）、`VaultCipher.kt`（加解密）

---

## 1. 总览

```
LedgerBook（账本，加密后落盘）
├── entries            List<LedgerEntry>   流水（唯一的"真相"）
├── periods            自定义账期
├── budgets / goals / subscriptions / assetAccounts
├── settings           VaultSettings（含本地 AI 相关设置）
├── customRules        List<CategorizationRule>  用户自定义分类规则
├── favoriteLocations  常用地点
├── aiMessages         List<LedgerAiMessage>     AI 对话记忆
├── aiFocusEntryIds    上一轮命中的流水 id
├── merchantCategories Map<String,String>        商户 → 分类（千问学到的）
├── captureTemplates   Map<String,CaptureTemplate> 通知骨架 → 模板
├── capturePathStats   Map<String,int>           模板/缓存/千问 各处理了多少条
├── captureDelayProfile Map<String,int>          各来源观察到的最大通知延迟
└── captureSequence    Map<String,int>           "微信>银行" 这类顺序计数
```

## 2. LedgerEntry（流水）

```dart
id                    唯一 id（自动记账时 = 通知 id，保证幂等）
title                 标题
merchant              商户
counterpartyName      付款人 / 收款方（只在通知明确写出时才非空）
note                  备注
amount                金额（double，永远来自通知解析）
type                  expense / income / transfer
categoryId            分类 id
channel               PaymentChannel 支付渠道
occurredAt            发生时间
tags                  List<String> 标签（来源、场景、"待确认"、"千问整理"…）
linkedRefundEntryIds  关联的退款流水 id（退款绑定）
locationInfo/latitude/longitude   位置
mood                  ExpenseMood 心情（无心情/冲动解压/开心庆祝/疲惫犒劳/emo抚慰/平静松弛）
autoCaptured          是否自动记账产生
sourceLabel           来源标签（微信/支付宝/银行…）
fundingAccount        资金来源账户，例如 "招商银行 ••8821"      ← 本轮新增
autoMergeKey          合并键（判断是否同一笔）
autoProfileId         档案 id（多档案隔离）
autoPostedAtMillis    通知时间戳（毫秒）
manualOverrideFields  用户手动锁定过的字段（合并时不被覆盖）
inferredFields        Set<String> 哪些字段是**推测**的            ← 本轮新增
```

### 2.1 FACT 与 INFERRED

```
FACT（事实，永不重写）      amount / type / occurredAt / fundingAccount / channel
INFERRED（推测，可重跑）    title / merchant / counterpartyName / categoryId / tags / note / mood
```

写入规则（`_captureToEntry`）：只有千问真的提供了某个字段，才把它加进 `inferredFields`。
价值：半年后换一个更好的模型，可以**只重跑 INFERRED 的字段**，金额、时间、卡号一律不动。

## 3. AutoCaptureRecord（队列里的一条通知）

```
id, title, merchant, counterpartyName
rawBody          通知原文（用于核对与生成）
scenario         merchantPayment / codePayment / transferPayment / refund / platformPayment …
amount, entryType, channel, source, capturedAt, postedAtMillis
confidence       解析置信度
defaultCategoryId, profileId, mergeKey, relatedSources
```

对应 Kotlin 侧 `AutoCaptureStore` 里的 JSON；Dart 只读，ack 之后才出队。

## 4. CaptureTemplate（通知模板）

```dart
class CaptureTemplate {
  final String categoryId;  // 千问第一次判断出的分类
  final int hits;           // 被复用了几次
  final int misses;         // 用户改过几次（>0 即降级为不可信）
}
```

键 = 通知骨架（数字挖成 #、截断 60 字、前缀来源），见《02-算法-通知到账单》$3.2。

## 5. 设置项 VaultSettings

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| confidentialModeEnabled | true | 机密模式（金额打码） |
| maskAmounts | true | 金额打码 |
| quickLockOnBackground | true | 后台自动锁定 |
| autoCaptureEnabled | true | 自动记账总开关 |
| defaultExpenseCategoryId | daily | 千问没给结果时的备用分类 |
| wechat/alipay/…/bankEnabled | true | 各来源开关 |
| locationMode | off | 记录位置的方式 |
| autoRecordLocation | false | 记账时顺便记位置 |
| voiceInputEnabled | true | 语音输入 |
| localAiModelId | qwen3-06b-q4 | **问答/分析**用哪个模型 |
| aiCaptureSpec | 见下 | 生成账单的"风格要求"（用户可改） |
| autoAiCaptureEnabled | false | 旧字段，仅为兼容历史数据保留（自动记账现在一定走千问路径选择逻辑）|

默认风格要求（`defaultAiCaptureSpec`）：

```
标题写成"商家 + 用途"（例如"麦当劳 午餐"）；商户写品牌名，不要写"未识别商户"；
分类从给定列表里选最贴近的；标签最多 2 个短词。
```

## 6. 查询与统计相关的运行时结构（不进账本）

| 类型 | 生命周期 | 说明 |
| --- | --- | --- |
| LedgerQuerySpec | 一次提问（上一轮存在控制器里） | 查询条件，含 continueContext |
| LedgerQueryOutcome | 一次提问 | 给模型看的结果文本 + 命中的流水 id |
| LedgerSearchHit | 一次模糊检索 | lexical / semantic / score |
| LedgerStatsIndex | 控制器内缓存 | 按天按月聚合，版本变了重建 |
| LedgerAnomaly | 每次渲染现算 | 异常提醒（重复/涨价/大额） |
| AiCaptureFields | 一次通知处理 | 千问给的字段 + categoryConfidence |

## 7. 序列化与兼容

### 7.1 三条规则

1. **加字段必须给默认值**：`json['x'] as T? ?? 默认值` —— 老账本读进来不会炸；
2. **集合字段做类型过滤**：`(json['x'] as List<dynamic>? ?? const []).whereType<String>()`；
3. **枚举用名字**：`EntryType.values.byName(...)`；未知值走 `orElse` 兜底。

### 7.2 本轮新增字段的兼容性

| 新增 | 老账本读入结果 |
| --- | --- |
| fundingAccount | 空字符串（显示时自动省略） |
| inferredFields | 空集合（视为全部是事实，不重跑） |
| merchantCategories / captureTemplates / capturePathStats / captureDelayProfile / captureSequence | 空 Map（等于"还没学过"） |
| aiMessages / aiFocusEntryIds | 空列表（对话从零开始） |
| aiCaptureSpec | 默认风格要求 |

### 7.3 迁移与清理

- `LedgerBook.withoutLegacySeedData()`：清掉早期版本内置的示例数据，但保留真实记录（按内容指纹比对）；
- UTC 时间的历史数据会在读取时**迁移为本地时间**（`utc auto-captured entries migrate to local device time` 测试覆盖）。

## 8. 目录与文件

| 内容 | 位置 | 加密 |
| --- | --- | --- |
| 账本本体 | 应用私有目录，AES-GCM | ✅ |
| 通知原文收件箱 | SharedPreferences（`jier_raw_notifications`） | ❌（应用私有，仅支付类） |
| 待处理队列 | SharedPreferences（`jier_auto_capture`） | ❌（同上） |
| 模型文件 | 应用外部私有目录 `Download/*.gguf` + `.verified` | ❌（公开模型） |
| 生物识别口令 | Android Keystore + EncryptedSharedPreferences | ✅ |

隐私原则：**只有"看起来像支付"的通知才会入库**，微信聊天等内容根本不落盘。
