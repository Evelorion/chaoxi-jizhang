## 3. 签名：换电脑后必须先做这一步

android/debug.keystore 被 android/.gitignore 忽略（签名文件不该进仓库），
所以新克隆的仓库在 Windows 上可能直接踩到：

```
Execution failed: Keystore file not found / keystore password was incorrect
```

重建一个本地调试签名即可（**debug 专用，不是发布签名**，注意整条命令是一行）：

```bash
keytool -genkeypair -v -keystore android/debug.keystore -storepass android -keypass android -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Android Debug,O=Android,C=US"
```

android/app/build.gradle.kts 里已写好：只要该文件存在，debug / profile / release
三种构建都用它签名，不会再去找 ~/.android/debug.keystore。

## 4. 真机验证配方（adb）

### 4.1 装包并启动到解锁后

```bash
adb install -r build/app/outputs/flutter-apk/app-release.apk
adb shell am force-stop com.aline.jier.jier
adb shell am start -n com.aline.jier.jier/.MainActivity
# 口令 123456（测试库）→ 点解锁
```

### 4.2 往待处理队列里塞一条通知

```bash
adb shell "run-as com.aline.jier.jier sh -c 'echo <base64> | base64 -d > /data/data/com.aline.jier.jier/shared_prefs/jier_auto_capture.xml'"
```

run-as 要求 debuggable 构建（debug 包或 profile 包）。

### 4.3 看队列与原文

```bash
adb shell "run-as com.aline.jier.jier cat /data/data/com.aline.jier.jier/shared_prefs/jier_auto_capture.xml"
adb shell "run-as com.aline.jier.jier cat /data/data/com.aline.jier.jier/shared_prefs/jier_raw_notifications.xml"
```

### 4.4 看后台服务是否在跑

```bash
adb shell "dumpsys activity services com.aline.jier.jier | grep -i CaptureDrain"
```

### 4.5 看真实日志（模型相关都带 [LocalAi] 前缀）

```bash
adb logcat -d | findstr /C:"LocalAi" /C:"flutter"
```

### 4.6 性能与卡顿

```bash
adb shell dumpsys gfxinfo com.aline.jier.jier reset
rem …操作…
adb shell dumpsys gfxinfo com.aline.jier.jier | findstr /C:"Janky" /C:"Total frames"
adb shell top -n 1 | findstr jier
```

### 4.7 截图

```bash
adb shell screencap -p /sdcard/shot.png
adb pull /sdcard/shot.png ./shot.png
rem 注意：不要用 PowerShell 的 > 重定向保存 PNG，会损坏文件
```

## 6. 已知限制（如实列出）

| 限制 | 说明 |
| --- | --- |
| x86_64 模拟器不能推理 | 推理库只有 arm64；模拟器只能验证"队列等待 / 降级"这一层 |
| flutter analyze 有 20 条 info | 全部在早期代码里（大括号风格、插值写法），**无 error / warning** |
| 推理仍在 App 进程 | 后台靠前台服务保活；不是独立原生 AI 服务 |
| 商户别名未归并 | MCD 03291 与 麦当劳成都001店 目前算两个商户（下一步计划） |
| 部分退款未做净额 | 退款能绑定原支出，但 refunded_amount / net_amount 还没建 |
| 向量是 TF-IDF 稀疏向量 | 不是神经网络 embedding，跨词语义有限（接口已留好替换点） |
| 温度 / 电量节流未做 | 目前是"队列空就完全不动"，还没有"充电时才批处理"的策略 |

## 7. 提交规范（本项目实际使用）

```
feat(android): …   原生侧（通知、队列、下载、服务）
feat(ai): …        本地模型相关
feat(ledger): …    记账引擎（解析、合并、检索、统计、异常）
feat(app): …       主应用界面与数据模型
fix: …             缺陷修复（写清复现路径与根因）
docs: …            文档与截图
style: …           仅格式
```

提交信息写清"**为什么**"和"**根因**"，例如：

```
fix: 所有手机都被误判成不支持本地 AI

根因：canRunLocalAi 探针写在取 modelId 之后，参数缺失先抛异常，
      Dart 侧把通道错误当成"设备不支持"。
现在自检放在取参数之前，并区分"明确不支持"与"通道异常"。
```
